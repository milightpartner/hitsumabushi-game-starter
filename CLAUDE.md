# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A starter template for building a game for **ひつまぶし (OmoshiroGamePortal)** using `@milightpartner/hitsumabushi-sdk`. This repo has no connection to the Portal's own codebase or infrastructure - it's a standalone game that talks to the Portal purely through the SDK's `postMessage`-based protocol once embedded in an `<iframe>`.

## First step: run `npm install`

`npm install` does two things:
1. Installs `@milightpartner/hitsumabushi-sdk` (requires `GITHUB_PACKAGES_TOKEN` in the environment - see README.md's Setup section if this fails with a 401/404).
2. Runs `postinstall` (`hitsumabushi init`), which copies the `hitsumabushi-game-developer` skill into `.claude/skills/hitsumabushi-game-developer/` - **read that skill before implementing anything**. It has the full API reference, the design principles this Portal expects (10-second-to-start matches, neon/cyberpunk visual language, OBS transparent-mode support), the mandatory rematch/spectator rules, and three working reference templates (minimal/turn-based/realtime) to build from.

`.claude/skills/` is gitignored and regenerated by `postinstall` - never hand-edit it, and don't worry about committing it.

## Commands

```
npm install       # installs the SDK + the AI skill (postinstall)
npm run dev       # hitsumabushi dev - local multiplayer test harness, no Portal needed
```

There is no build step by default - `index.html` is self-contained and uses an import map so it runs directly under `npm run dev` without a bundler. If you introduce a bundler (Vite, etc.) for a more complex game, remove the `<script type="importmap">` block in `index.html` - the bundler resolves the bare `@milightpartner/hitsumabushi-sdk` import at build time instead.

## What's already in this repo

- `index.html` - the actual game, currently just the SDK-initialization skeleton from the skill's `templates/minimal/` (spectator lock + rematch reset already wired up - keep both when you replace the game logic).
- `manifest.json` - declares player count/result model to the Portal. Update `gameId`/`title`/`players`/`resultModel` to match your actual game once decided.
- `guide.md` - stub for the Portal's game-guide article system (optional, see its own comment for what it's for).

## Ground rule

This repo can't reach into `OmoshiroGamePortal`'s own source or infrastructure, and shouldn't try to. If something seems like it needs a Portal-side or SDK-side change (a missing SDK API, a Portal behavior that seems wrong), don't work around it locally - flag it to the user and suggest filing an issue on `milightpartner/OmoshiroGamePortal` instead. The skill's own instructions cover this in more detail.
